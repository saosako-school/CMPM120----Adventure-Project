A simple adventure game by Sydney based on a simple adventure game engine by [Adam Smith](https://github.com/rndmcnlly).

Code requirements:
- **4+ scenes based on `AdventureScene`**:
    - Scene 1: Hallway
    - Scene 2: MathClassroom,
    - Scene 3: OrchestraClassroom,
    - Scene 4: EnglishClassroom
    - Scene 5: ChemClassroom
    - Scene 6: ExitDoor
- **2+ scenes *not* based on `AdventureScene`**: 
    - Scene 1: StartScene
    - Scene 2: EndScene
- **2+ methods or other enhancement added to the adventure game engine to simplify my scenes**:
    - Enhancement 1: doorAdd(); adds door objects that can transport the player to different scenes
    - Enhancement 2: made this.sh and this.sw which scale to the height and width of the canvas I drew the assets on (so this.sh is 1/180 of the height since I drew my assets on a canvas with a height of 180 pixels), which made calculating where to place objects much easier since I knew their x and y locations on the smaller canvas I drew them on.
    - Enhancement 3: Threw all the inventory side bar stuff into a separate function, sideUIStuff(). This allowed me to layer the sidebar on top of other assets that I added during onEnter() by calling that function, and also make the side bar on the left or right part of the screen, which was necessary for the rooms on the left (as in, the side bar would cover up the door back to the hallway in the Orchestra and math rooms).
    - Enhancement 4: made a function enterCode() because the puzzles relied almost exclusively on entering codes into objects, like the filing cabinet, so adding the function made it so that I did not have to continuously write out all the code every time I had to make an object act in that way. This function would disable the inputs to all other objects in the classroom and make a screen popup where the player could submit their code (which would either give the player the item, or tell the player that they are wrong). This goes hand-in-hand with adding the codes, and readBook to the init function. These essentially worked the same as the inventory and would ensure that the player's entered codes would remain the same, even if they went to another scene, and readBook would ensure that the player could rip down the poster at any point after they read the book.
    - Enhancement 5: displayed all text with a bitmap font. I think that my reasoning was that it would look funny to have a pixel art game without a pixel art font. At the very least, sizing things felt easier with the bitmap font.
    - Enhancement 6: made a function fadeObject() which would make a tween that fades an object in or out by a certain amount depending on the pass arguments. I used this for almost all of my tweens, so having a simple function saved me a bit of time.
    - Enhancement 7: made a function investigate() which pulls up a screen with text (the text depends on the args provided) that can be read in parts. The different parts can be read by pressing the left and right arrows to go to the next or previous parts of the text. There is also an exit button that will remove the screen if the player clicks it.

Experience requirements:
- **4+ locations in the game world**: 
    - Scene 1: Hallway
    - Scene 2: MathClassroom
    - Scene 3: OrchestraClassroom
    - Scene 4: EnglishClassroom
    - Scene 5: ChemClassroom
    - Scene 6: ExitDoor
- **2+ interactive objects in most scenes**:
    - Hallway: there are 4 door objects, each one leading to a different scene when clicked on and a description of where they lead when hovered over. There is also a small arrow that does much the same as the doors, except the text when it is hovered over is slightly different. So, there are 5 interactive objects in this scene (4 doors and the arrow).
    - ChemClassroom: There is a whiteboard, a door back to the hall, and a lockbox in this scene. The whiteboard has a problem on it and hovering over the whiteboard will show a message to point this out to the player. When clicking on the lockbox, the player is prompted to input 3 numbers by pressing up and down arrows above said numbers to increment and decrement them. The player can press a button to exit this input screen and enter to try to see if they got the code right. If they did, they gain an item. If not, a message informs them of that nothing happened. After gaining this item, the lockbox becomes non-interactable and displays a different message. There are 11 interactive objects in this scene then (the door, the whiteboard, the lockbox, an up and down button for incrementing and decrementing each number, which is 2 buttons times 3 numbers, so 6 of these buttons, and an exit and enter button).
    - EnglishClassroom: There is a whiteboard, a poster, a door back to the hall, and a book in this scene. Hovering over the whitebord points out that there is nothing on the whiteboard. Hovering over the poster tells the player what it says, and hovering over the book tells the player that it is a collection of Shakespeare plays. Clicking on the book will bring up a small screen (much like the one that appears when a player needs to enter a code) that displays the text of the book. Since the text is quite long, it is broken up into multiple parts which can be accessed by clicking on an arrow the points right to go to the next part, or an arrow that points to the left to go to the previous part. There is also an exit button to exit this screen. After interacting with the book, the player will be able to click on the poster, which will tear it down, reveal a hole, and give the player an item. There is also text if the player hovers over the hole. There are 7 interactive objects in this scene (door, poster, hole, book, whiteboard, left and right arrows).
    - MathClassroom: There is a whiteboard, a filing cabinet, and the door back to the hall. This scene works almost exactly like the ChemClassroom scene, except with a filing cabinet instead of a lockbox, so I'm not going to waste your time by re-explaining it. There are 11 interactive objects (hallway door, whiteboard, filing cabinet, 6 incrementing/decrementing buttons, an exit button, and an enter button).
    - OrchestraClassroom: There is a whiteboard with some music notes on it, a theory book on the whiteboard, a note on the ground, and the two lockers. Hovering over the whiteboard points out that there are notes on it, hovering over the theory book tells the player that it is a beginner music theory book, hovering over the note on the ground tells the player that it is a note, and hovering over the two lockers gives a brief description of unique characteristics they have (like a sticker on one, or a smudged out word on the other). Clicking on the theory book brings up a text screen (like the one from EnglishClassroom), where the player can read different parts of the text by pressing the left and right arrows and exit by pressing the exit button. The note does the same thing when clicked on. If the player clicks on the lockers they can input a code (with 4 letters this time instead of 3 digits) using much the same mechanisms as previously described for the lockbox in ChemClassroom, except with 4 letters instead of 3 numbers. There are 18 interactive objects (the door, the whiteboard, the two lockers, the note, the theory book, the 8 incrementing/decrementing buttons for entering codes, the enter button, exit button, and the left and right button).
    - ExitDoor: There is a door, a wooden plank, a keyhole, and a combination lock in this scene. Hovering over the door, the plank, the keyhole, and the combination lock will give the player a description of the object. Clicking on the padlock, the wooden plank, or the keyhole will remove them (for the plank and padlock) or unlock them (with the keyhole) if the player has the correct items. Clicking on these items without said objects will tell the player that they do not have the right items. Clicking on the door without removing/unlocking everything will tell the player about one of the things they still need to unlock/remove before they can use the door. If everything has been unlocked/removed, hovering over the door will tell the player that they are free and clicking on the door will send the player to an end screen scene. There are 4 interactive objects in this scene (the door, the keyhole, the plank, and the combination lock).
- **Many objects have `pointerover` messages**:
    - Hovering over any doors in the hallway or in the classrooms will tell the player where they lead and hovering over the arrow in the hallway, or at the door at the end of the hallway, will ask the player if they would like to go to a certain location which they will go to if they click on the arrow.
    - Hovering over the whiteboards in the classrooms tells the player what is on the whiteboards. Most other items in the classrooms tell the player what they are when hovered over or describe a small action that the player's character performs in reference to the object that does not have any material effect on the game world.
- **Many objects have `pointerdown` effects**:
    - Clicking on any doors will lead the player to a different scene (except for the final door, which can only send the player to a different scene if certain conditions are met).
    - Clicking on the theory book, the note, and the book, will bring up a screen where the player can read some text while disabling all interactive capabilities of the other objects in the scene. These screens have buttons that when clicked on bring up the next part of the text or the previous part. These screens also have exit buttons that, when clicked on, remove the screen and make all interactive objects in the scene interactive again.
    - Clicking on the lockers, the filing cabinet, or the lockbox will disable all other interactive elements for the other objects in the scene and pull up a screen that the player can input into by pressing up or down arrows to increment/decrement numbers or letters, enter their input by pressing an enter button, and exit by pressing an exit button. Inputting the correct answer or pressing the exit button will re-activate all interactive elements of the objects in the scene (except for the object that the player input the code into if they player gets the code right, which will no longer have any pointerdown effects).
- **Some objects are themselves animated**:
    - The input screens (including all the buttons) for the codes are animated by fading in or out. This is also the case with the screens that just show text for the player to cycle through. The combination lock and the wooden plank also fade out when removed.

Asset sources:
- I drew each image asset myself (with exception to the bitmap font stuff) using Procreate on my iPad. I made all assets that I was going to use on one canvas (which was 320 by 180) on a bunch of different layers and made several copies of the canvas to isolate individual assets on each canvas, crop out all unnecessary space, and send it over to my computer for use.
- The bitmap font was NOT created by me in any way. If I had the time, I likely would have created my own font (though, it was unlikely that such an endeavor would be worth it considering that I'd come out with a similar, or inferior result, and would have spent way more time than I already have). In any case, the font (by which I mean the .xml and .png files for the font I used) was created by frostyfreeze. I downloaded a pack of these fonts from [here](https://frostyfreeze.itch.io/pixel-bitmap-fonts-png-xml), which I found when I was looking around for .xml and .png files for bitmap fonts (Phaser reqires both, which, as frostyfreeze notes, is difficult to come by, so they made the fonts for this reason).
